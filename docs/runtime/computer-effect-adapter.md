# Native computer broker integration

The computer effect core is integrated into `ComputerRuntimeService`, the existing single `PageRuntimeService` native callback router, the authenticated self-hosted app, and the signed target protocol. Page callbacks retain their original handler; computer dispatch, inspect and observe are selected by the finite producer method/adapter identity. Both model approval kinds share the same original pending `dots.approval` waiter and cannot send a second `runtime.approval.resolve`.

The server-owned Ryoko launch config accepts `nativeComputer: { executorId }`. The immutable executor ID must match the target configuration (target default `computer:${dotId}`); it is not necessarily the Dot ID. Authenticated discovery is `GET /api/runtime/computers?dotId=...`, followed by exact-executor status, `/screen`, `/actions`, `/control`, and GET-only `/api/runtime/computer-operations/:operationId` recovery. Agent standalone review uses conversation-scoped `/computer-actions`, `/:operationId/execute`, and GET recovery. Browser FE intent digests are stored separately from producer canonical proposal/input digests.

Production `index.ts` constructs the governed `ComputerService` with existing supervisor/master-token settings and an exact per-Dot executor mapping. `COMPUTER_QUALIFICATION_PATH` optionally names a bounded operator-reviewed JSON receipt. It must include matching protocol, Dot/executor IDs, receipt digest, individually qualified actions, exact target build and configuration digests, and `evidence: "target-host"`. The production loader rejects synthetic evidence. No qualification file is supplied or inferred. A signed target status must match the declared fingerprint; every target request carries that expected identity. Missing, changed or unobserved targets cannot execute. Authenticated setup/connect/status perform read-only discovery, never provisioning. Synthetic fixtures use explicitly synthetic fingerprints and deterministic ports; they cannot qualify a deployment.

Producer profile grants must include `dots_computer_observe`, `dots_computer_propose`, and each actually registered action tool such as `dots_computer_snapshot`, `dots_computer_files_read` or `dots_computer_files_write`. Owner UI permissions do not grant model policy. Registration uses the actual durable native grant revision, and current run generations come from producer `command.claimed` events, not callback/browser JSON. Initial revision zero is accepted by the pinned producer. Reconnect does not replay work.

Permissions and takeover update durable local fences before the native change. Lost changes remain locked/unknown and recover only from their exact target change receipt. Human takeover actions remain separately authenticated and never become broker effects. Bot handback requires a new actual snapshot; the independently captured owner PNG screen does not clear that requirement. Real screenshots retain their target capture timestamp and are checked against exact current scope and aggregate revision on delivery. Supervisor lifecycle outcomes remain unknown after response loss because the pinned supervisor has no operation-bound recovery proof; a target control acknowledgment alone cannot prove a lifecycle request completed.

Native unknown effects, owner intents, operation-family claims, reservations, redacted bytes and proof digests persist in the workspace database. Unknown BFF owner admission blocks new normal actions even if a crash preceded core admission. Safety takeover, revoke and emergency stop can still fence access. Every recovery route is read-only and does not mint a replacement operation ID.

Focused source checks cover core executor fences, the shared callback router, FE owner-operation recovery and the authenticated coordinator. The actual Node BFF → pinned Python producer → signed loopback target fixture uses a deterministic file executor, witnesses a target commit followed by response loss, restarts the BFF and producer, and reconciles the original operation with one dispatch and zero model calls. This is protocol/synthetic evidence only. Hardware browser, Docker supervisor, real shell/files sandbox and egress, persistent real profile volumes, target-host qualification and aggregate BE12 checks remain separate gates. The known cloud browser restrictions are preserved.
