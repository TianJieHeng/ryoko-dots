# BE11 migration and operational safety

The operational seams are integrated with the self-hosted BFF. Qualification below is synthetic and local unless explicitly stated. No actual user database, export, backup, credential, provider, deployment, account or system configuration was accessed or changed. Nothing was published. Do not infer BE12 or production readiness from the implemented operational tools.

## What is implemented

- Read-only legacy SQLite inventory with table counts and deterministic content digests; source sidecars with pending WAL/journal are refused by inventory rather than silently omitted
- Resumable inert legacy record archive with stable IDs, atomic batch checkpoints, immutable first records, conflicting-byte quarantine and tombstone non-resurrection
- An actual owner-pinned importer and paginated reader for a supplied, reviewed normalized history export, with original export digest verification, stable original conversation/message IDs and provenance, restart resume, conflict quarantine and zero command/tool replay
- Offline paired Dots DB, Ryoko DB and artifact-byte backup/verify/restore, explicit additional state resources, crash-retained WAL recovery only in the private snapshot copy, SHA-256/length manifest, private staging, path/symlink/hardlink rejection and atomic Linux no-replace publication
- Existing-age-tool encryption/decryption option; bounded regular-file-only USTAR decoding rejects links, devices, extensions, duplicate members and path traversal
- One process-tree lifetime gate for supervised Dots and its Ryoko child, excluding duplicate state owners and maintenance. There is no online backup path and no caller-provided `quiescent=true` shortcut
- Independent bounded readiness probes, bounded redacted numeric metrics, schema diagnostic digest, admission freeze and graceful draining; exact error text, prompts, personal memory and audio never enter this telemetry
- Native non-root service example and a separate hardened self-hosted Compose/image example with native TLS for non-loopback container binding, existing mounted owner secret, private port, resource limits and no Intelligence/managed Channels settings
- A transitive TypeScript AST check that production startup does not reach the retired managed executor/channel packages. Legacy source and regression tests remain intact; the suggested package change moves those build/test-only dependencies to development rather than deleting coverage

## Read-only legacy inventory

Use only an authorized supplied offline source or a normalized snapshot. The utility never opens the source read/write, changes PRAGMAs on disk, repairs the source or creates a source WAL/SHM. `immutable=1` would ignore pending WAL, so pending WAL/journal is explicitly rejected. For crash-retained WAL, use `safe_state snapshot` under the exclusive gate first; the recovery happens only inside the temporary copy.

Example operator commands (not performed by this work):

    python3 scripts/operations/legacy_inventory.py inventory --source /private/snapshot/dots.sqlite --namespace stable-legacy-installation
    python3 scripts/operations/legacy_inventory.py stage-archive --source /private/snapshot/dots.sqlite --namespace stable-legacy-installation --destination /private/migration/legacy.sqlite --batch-size 100

The report inventories settings/global preferences, memories, tasks/runs/events, Spaces/Dots, frozen learning-container/enrollment columns, thread/task/page/call mappings, captures, page versions and computer permission/audit identity records when their known tables exist. Unknown tables are listed, never silently called migrated. Browser session/token tables are deliberately excluded from the inert migration archive. Full paired backup includes authentication tables because it is a recovery backup and must be protected accordingly.

Stable record IDs hash the operator's stable source namespace, table and original primary-key values; source digest is provenance, not part of record identity. Never change namespace between retries. Each batch commits rows and cursor together. First source bytes are retained. Changed bytes under the same ID are quarantined and require review, never silently overwritten. Tombstones prevent reinsertion and retain no resurrected payload in quarantine. Do not use this archive as a scheduler, memory provider or authorization source.

Historical Intelligence access is unavailable until an authorized export is supplied. SQLite mappings do not contain all managed conversations. Inventory always says `intelligenceHistory.complete=false` and `fullMigrationComplete=false`; archived rows are not evidence of complete cloud history or provider erasure.

## Supplied historical conversation import and reader

`history_import.py` is a real inert history importer, not a live-session replay adapter. Supply both the original authorized export and a reviewed normalized v1 envelope. No Intelligence export API shape is invented; normalization for an actual provider export must be reviewed against that export's documented version and checked for omissions. The exact allowed normalized shape is in `history-export-contract.md`.

    python3 scripts/operations/history_import.py import --archive /private/migration/history.sqlite --owner pinned-owner --namespace stable-legacy-installation --original-export /private/export/original.json --normalized-export /private/export/normalized.json --batch-size 50
    python3 scripts/operations/history_import.py inspect --archive /private/migration/history.sqlite --owner pinned-owner --namespace stable-legacy-installation --legacy-id original-thread-id --offset 0

The archive is pinned to one owner. The expected owner and source namespace are explicit operator inputs and must match the reviewed envelope. Original raw export bytes are hashed and must match provenance. Import is bounded to 32 MiB normalized JSON, 10,000 conversations, 100,000 messages, 256-character IDs, 500-character titles and 262,144-character message text. Counts, duplicate IDs and unexpected authority fields are rejected before destination mutation. Each conversation's messages and batch checkpoint commit atomically. Reruns after restart are idempotent. Changed content is quarantined while the first archive remains readable. A partial source is clearly reported partial even if every supplied row imported.

Both the CLI inspector and TypeScript `LegacyHistoryReader` return plain text for user/assistant messages in original order, original IDs, stable archive IDs, original-export digest, pagination and omitted non-display record counts. System/tool/unknown messages are retained as private inert SQLite evidence but never returned as display text or forwarded into an agent. The archive never connects a session, injects memory, enrolls learning, accepts a review, submits a command, dispatches an effect or schedules work. It is explicitly `readOnly=true`, `executable=false`, `trustedAsInstructions=false`, `provenance=imported-archive`.

The stable `(namespace, legacyId) -> archive conversation ID` mapping resolves old links. An authenticated UI must label these as imported historical archives, render text without executing HTML, and never offer a "resume as original command" operation. Optional copying of selected text into a new user-authored prompt is a separate action, not migration. A native Ryoko import requires a producer-defined offline maintenance/history import contract that proves owner/conversation lineage and inserts inert committed records without queue/admission/effect creation. No such exact producer method is invoked or claimed by this package.

## Required consistent boundary

Online paired snapshots are intentionally unsupported. Sequential SQLite online backup calls would not establish a consistent cross-database/artifact boundary.

Before backup, the operator must prove all writers are in the single supervised process tree, stop that service, and keep all other native/Compose/cron/worker starts disabled. Both normal service startup and maintenance must use the same canonical, private, never-replaced gate file. The lifetime wrapper holds an exclusive POSIX lock while supervising Dots and its process tree and passes the descriptor into the direct Dots child, so killing only the wrapper does not release the direct owner lock; Linux subreaping and process-group termination/reaping prevent an ordinary orphaned Ryoko child from releasing the gate early. On a systemd host use `KillMode=control-group`; container shutdown must retain its namespace/init process until children exit. Daemonization, escaped process groups, separately started producer/cron processes, other containers using another gate inode, writable peer hosts and uncooperative root/same-UID writers invalidate the proof. The Dots stdio transport explicitly forwards the inherited descriptor to its owned Python producer as FD 3. A synthetic wrapper → Node → Python kill test proves the owned Python process still excludes snapshots after both wrapper and Node receive SIGKILL. Arbitrary producer descendants do not automatically inherit it through every Python subprocess call: killing all gate holders can still leave an independently alive writer unless service/cgroup/container stop semantics kill the whole tree. Host qualification must establish full-tree shutdown and absence of such survivors before maintenance. An advisory lock cannot make an uncooperative writer safe.

`safe_state snapshot` refuses a held gate, acquires the same exclusive lock before reading anything, copies all declared DB/WAL/SHM/journal/artifact bytes, normalizes SQLite only in the copy, validates SQLite integrity, checks source metadata is unchanged across the copy, hashes every output file and publishes the directory with `renameat2(RENAME_NOREPLACE)`. Source change, insufficient disk, corrupt DB, unsafe path or publication conflict fails with no advertised partial snapshot. Process kill may leave a private `.snapshot-*` staging directory; it is not a backup because there is no published generation. Remove such staging only after inspecting it and obtaining any required deletion authorization.

A before/after stat check is a secondary race detector, not a substitute for the gate's writer census. Snapshot consistency is conditional on the operator's verified offline ownership proof. Do not claim "provably quiescent" for an arbitrary running installation based on file stability alone.

## State scope and commands

The reviewed JSON state plan lists every required SQLite database and artifact/mapping/outbox/retirement store below one private state root. It must contain `dots_db`, `ryoko_db` and `artifacts`; additional profile databases, transcript stores, command/result/delivery databases, history archives and tombstones must be listed from the actual pinned producer/deployment inventory. Their real path names are deployment-specific; `state-plan.example.json` is illustrative and is not proof of complete state coverage. Mapping/outbox records in Dots' SQLite are automatically included with that database. Artifact roots outside the state root must be relocated through separately authorized deployment work or a reviewed extension; do not add symlinks to evade the boundary.

No profile `.env`, TLS private key, authentication credential file, whole home directory or unrelated private data is auto-discovered. Existing secrets and keys need the operator's existing secret backup policy; a paired state backup alone is not a replacement. Owner token secret loss and rotated session credentials are separate recovery cases.

    python3 scripts/operations/safe_state.py snapshot --plan /private/operator/state-plan.json --gate /private/gate/state.lock --destination /private/backups/generation-001
    python3 scripts/operations/safe_state.py verify --bundle /private/backups/generation-001
    python3 scripts/operations/safe_state.py restore --bundle /private/backups/generation-001 --gate /private/gate/state.lock --destination /private/restored/generation-001

Parent output directories must already exist with mode 0700 under the same owner. Files become 0600. Symlink components and hardlinked files are rejected. Restore verifies every declared file and actual file set, sizes/digests, required resources and SQLite integrity, then publishes a new generation. It never overwrites the running or prior generation and never starts services. No delete, symlink swap, credential reset or network action is hidden in restore.

A digest manifest detects corruption, not an attacker who can replace both bytes and manifest. Protect snapshots as private owner material and use authenticated encryption before moving them off-host:

    python3 scripts/operations/safe_state.py encrypt --bundle /private/backups/generation-001 --destination /private/encrypted/generation-001.age --age-binary /usr/bin/age --recipient EXISTING_AGE_PUBLIC_RECIPIENT
    python3 scripts/operations/safe_state.py decrypt --encrypted /private/encrypted/generation-001.age --destination /private/decrypted/generation-001 --age-binary /usr/bin/age --identity /private/existing-age-identity

The age binary must be a trusted operator-installed executable. No key is generated or transmitted by these helpers. Encryption leaves the private plaintext source intact; deleting it is an explicit retention action. Decryption verifies age's success and validates bounded regular-file-only USTAR output before atomic publication. The actual age executable was absent in the qualification environment: crypto round-trip is **not qualified**. Parser tests use a clearly labeled synthetic passthrough executable and establish only path/format handling, not encryption.

## Activation, single-authority rollback and privacy

1. Freeze all Dots admissions. Quiesce legacy Dots scheduler and record permanent retirement for each migrated job, with unresolved leases/claims reconciled. BE07 cutover must consume actual durable retirement evidence and stable occurrence IDs; archived task rows do not authorize new scheduling
2. Wait for active adapters/HTTP requests to settle. Persist unknown outcomes. Stop Dots and its one producer as a process tree. Do not infer mission cancellation from disconnect, hangup or stopped UI
3. Verify gate ownership/writer census, capture the complete paired snapshot and record exact consumer/producer/schema/config/image pins. Rehearse restoration to an isolated generation with network and providers unavailable before changing routing
4. Inspect the restored generation and compare expected records, page/artifact hashes, mapping/outbox/retirement receipts, tombstones and exact pins. Run schema/auth/session revocation and producer qualification checks before any real activation
5. Start one explicitly accepted cohort only. Do not simultaneously run legacy DotAgent, Dots timer, another Ryoko scheduler, another Slack ingress or a second deployment against the same profile
6. If rolling client code/config back, freeze admissions first. Already accepted Ryoko missions, deliveries, unknown outcomes and schedule occurrences remain owned by Ryoko until resolved. Never replay them through the old model loop. Retain journals, mappings, artifact versions and durable retirement fence
7. A point-in-time state rollback after external actions is not effect rollback. Reconcile post-snapshot accepted work and unknown effects against external receipts before re-enabling execution. If old code cannot read the retained schema, keep the new authority paused or choose an explicitly reviewed compatible restore; do not auto-down-migrate or discard new receipts

Recommended retention must be chosen by the operator, not silently enabled: keep an encrypted pre-cutover snapshot until migration acceptance, plus a bounded recovery window aligned with actual data-retention requirements. Record location, owner, generation, key custodian, expiry and deletion receipt. Do not erase a last usable copy before a verified restore and explicit retention authorization.

Deletion is not automatically propagated to old snapshots or third parties. Keep durable tombstones in the current state and replay reviewed erasure metadata into any restored generation before enabling reads. Archive imports refuse tombstoned identities. A real erasure workflow must remove applicable archived payloads/quarantine copies, enforce backup expiry and document where immutable retention prevents immediate deletion. Provider-held history, Slack messages, delivered artifacts and personal memory harnesses require their own authorized export/delete capabilities; local erasure never certifies third-party erasure. No such deletion or retention scheduling was performed.

## Readiness, telemetry and shutdown

Liveness is only process health. Authenticated readiness exposes independent surfaces, preserving healthy history reads when Slack, voice or computer is unavailable. Absent adapters return `unconfigured`; probe exceptions/timeouts return `unavailable`. Scheduler ownership, actual memory health, workflow-list inspection, computer target status and voice media acceptance cache only a state/epoch for 15 seconds. They remain `unavailable` until observed and expire without performing network work from readiness. Slack uses its synchronous current policy/binding/status check. Artifact readiness requires a registered native session; it is not an arbitrary provider health promise. Readiness does not certify live-provider or target-host qualification. The storage probe checks required schema table presence plus quick-check and returns only a schema digest/count, not raw SQL/data. Probe functions must be read-only cached/capability checks, never auto-start providers or download models.

Metrics are allowlisted counters for admission, replay gaps, stuck reviews, unknown effects/delivery, queue saturation, storage pressure and drain; numeric gauges cover lag, queue depth and free bytes. They contain no arbitrary labels/IDs/URLs/errors or payloads. Emit JSON to the existing private operator log sink. HTTP admission/drain counters are wired at the common ingress. Read-only gauges report actual Dots command queue/unknown, unresolved control, computer-owner unknown, browser/Slack delivery unknown, Slack queue, voice unknown, schedule unknown and available filesystem bytes. An uncalled replay-gap or stuck-approval counter is not observed health. These local ledger gauges do not certify global provider queue/lag or that an unresolved approval is stuck; those richer producer metrics remain unavailable. Authenticated metrics are not public endpoints.

The operational shutdown freezes API and signed Slack ingress synchronously, begins HTTP close and waits within one deadline. A successful drain stops Slack startup/worker/inspection activity, quiesces command recovery and producer reconnects, stops voice cleanup, drains actual native callback promises and closes ledgers/storage. On failure or timeout it exits nonzero without closing shared SQLite under unfinished work; the lifetime wrapper and qualified service manager must terminate/reap remaining writers. It has no cancel/replay callback. Command/admission stores must preserve accepted/unknown work before adapter close. The old shutdown helper remains for historical regression tests; production uses the operational drain. No legacy test is deleted.

## Required npm startup gate

`npm start` and the backend part of `npm run dev` invoke `scripts/start-self-hosted.mjs`. Set `DOTS_STATE_GATE_PATH` to the same absolute gate used for maintenance, whose existing parent is private (0700) and owner-controlled. The wrapper may create the initial lock file; never replace or delete its inode while any writer can exist. The default gate interpreter is `/usr/bin/python3`; a different trusted installed interpreter needs an absolute `DOTS_GATE_PYTHON`. The server refuses direct ungated startup before opening SQLite, including development. Backend development uses explicit restarts instead of Node watch-worker forking; Vite frontend HMR is unchanged. Docker and native service launchers already supply the inherited descriptor directly. None of these launchers provisions directories, services, credentials, TLS keys or real state.

Retained compatibility surfaces are owner-only local metadata/archive operations: `POST /api/spaces` creates a named Space without granting any agent/project access; `GET /api/tasks/:id` returns inert legacy task detail/history; `GET /api/conversations/:id/capture` returns an owned legacy capture or explicit `null` for a verified canonical conversation (canonical results use runtime artifact routes). No read starts a producer and legacy task mutations remain retired.
